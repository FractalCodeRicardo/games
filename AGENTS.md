# AGENTS.md

Guidance for AI coding agents working in this repository.

## Repository layout

This repo is a collection of small, standalone games. The root is **not** a
monorepo/workspace — there is no root-level Cargo manifest or build config, and
no shared tooling. Each game directory is its own project.

- **Rust + macroquad games** (each a standalone Cargo crate with its own
  `Cargo.toml` / `Cargo.lock`, gitignored `target/`):
  `flappy-bird`, `google-dinosaur`, `mario`, `pacman`, `road-fighter`,
  `space_invader`, `space-shooter`, `trash-garbage`, `world-domination`.
  Entry point: `src/main.rs`; submodules split by concern (`assets`,
  `components`, `consts`, `sounds`, etc.). Uses macroquad `0.4.14` (edition
  `2024`); some use `macroquad-platformer` / `macroquad-tiled`.
- **Lua + Usagi engine games**: `frogger`, `mineswepper`, `tetris`. Engine
  version pinned in generated docs: **Usagi 1.3.3** (Lua 5.5 runtime).

## Commands

### Rust games

- Run a single game: `cd <game-dir> && cargo run`. **Never run cargo from the
  repo root** — each game is its own crate.
- Build artifacts land in that game's own `target/` directory.

### Usagi (Lua) games

- Dev loop: `cd <game-dir> && usagi dev` (or `usagi dev <path>`). Live reload
  on save; **`F5` resets game state**. `usagi run` for no live reload,
  `usagi export` for shippable artifacts (gitignored as `export/`),
  `usagi tools` for the jukebox/tile picker, `usagi update` to bump the engine.
- After an engine update: run `usagi refresh` inside the game folder. It
  re-syncs generated files (`USAGI.md`, `meta/usagi.lua`, `.luarc.json`) and
  never touches `main.lua` or `.gitignore`.

### Setup

- Usagi install: `curl -fsSL https://usagiengine.com/install.sh | sh` (or
  `usagi update` to refresh the binary in place).

## Conventions and quirks

- **Usagi config**: prefer a `usagi.conf` at the project root. `_config()` in
  `main.lua` is **deprecated** (engine logs a warning; lower precedence than
  `usagi.conf`/frontmatter). Only `tetris/` currently has a `usagi.conf`.
- **Generated engine files**: `USAGI.md`, `meta/usagi.lua` (LSP stubs), and each
  game's `.luarc.json` are engine-managed — run `usagi refresh` rather than
  hand-editing. `.luarc.json` sets Lua 5.5 runtime, `+=`-style compound
  assignments, `workspace.library: ["./meta"]`, and 2-space indent.
- **Entry point**: `main.lua` exposes global `_init`, `_update(dt)`, `_draw(dt)`.
  Game state is held in a global `State` table built in `_init`.
- **Modules**: `require "name"` resolves `<dir>/name.lua` or `<dir>/name/init.lua`
  (dotted names become slash paths). Use `require` only — `loadfile`/`dofile`/
  `io` do not work in web/exported builds.
- **API surface** is globals: `gfx`, `input`, `sfx`, `music`, `effect`, `util`,
  `usagi`, plus top-level engine constants. Full reference: engine `USAGI.md`
  and stubs in `meta/usagi.lua`.
- **Input**: use action constants (`input.LEFT`, `input.RIGHT`, `input.UP`,
  `input.DOWN`, `input.BTN1..BTN3`) with `input.pressed`/`held`/`released`;
  raw key reads (`input.key_pressed(input.KEY_*)`) bypass the keymap — fine for
  dev hotkeys, not for remappable game actions.
- **Dev-only**: GIF recording via Ctrl/Cmd+G in `usagi dev` builds.
- Asset directories vary between games (`sfx/`, `music/`, `sprites.png`,
  `data/`); `frogger/` notably predates the current layout and uses `audio/`.

## Verification

- **No tests, linters, formatters, CI, or task runner exist in this repo.**
  Do not invent or assume verification commands; nothing automated is set up.
- Rust games: `cargo build` inside the game directory is the practical check
  (macroquad needs a display/X11 context; a headless environment may fail at
  runtime rather than compile time).
- Lua/Usagi games: no automated checks apply.

## Current state / gotchas

- `tetris/` is mid-refactor: input handling was moved behind an injected mode
  object (`keyboard_mode` implements the move callback; constructed via
  `game.new(config, mode)`). Preserve in-progress changes.
- `tetris/` currently has **uncommitted WIP** (`game.lua`, `wall.lua`,
  `keyboard_mode.lua`). Do not overwrite or revert them.
- `frogger/` uses `_config()` with `Constants`-driven sizing and has no
  `usagi.conf` yet.
